# 0009 前端 js/ 与 pages/ 双轨处置

## 背景

前端并存两套心智模型：`frontend/src/js/`（326 文件，传统 DOM 模块）与 `frontend/src/pages/`（232 文件，React）+ `pages/reader/legacy/`（17 文件）。新功能无强制归属规则，两套风格继续各自生长，是认知负载最弱项（第四律 3 分）的核心来源。

## 决策

- **新功能只写 `pages/`（React）**；`js/` 不再承接新逻辑，只做存量维护。
- **归属标注 + 季度收敛**：每个 `js/` 模块标注 `保留 / 迁移 / 删除`，目标文件数 550 → 250。
- **禁止无标注的新增**：`js/` 新增模块必须先在标注清单登记去向，否则评审不通过。
- `legacy/` 只 re-export 或兼容旧调用方，不放新业务逻辑（同 ADR 0004 对 `legacy/` 的约定）。

## 后果

- 双轨收敛由「季度评审」驱动，而非一次性迁移，风险可控。
- `pages/` 成为唯一入口心智模型，新成员只需学一套。
- `js/` 存量的标注责任落在各模块 owner，需配合 code review 强制。

## 替代方案

- 一次性全量迁移到 React：理论更干净，但 300+ 文件同时迁移风险过高，会长期阻塞正常迭代。
- 放任双轨自然生长：认知负载持续累积，第四律评分不会回升。
