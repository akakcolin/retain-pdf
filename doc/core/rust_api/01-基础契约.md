# 基础契约

这篇只讲最基础的读法。

## 响应包装

所有业务接口统一是：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

读取顺序：

1. 先看 HTTP 是否 `2xx`
2. 再看 `code`
3. `code === 0` 再读 `data`

不要直接读顶层 `items`、`stage` 或 `failure`。

边界情况：

- HTTP 非 `2xx`：按网络或服务错误处理
- HTTP `2xx` 但 `code !== 0`：按业务错误处理
- `code === 0` 且 `data == null`：按“成功但无业务载荷”处理
- 字段应在 `data.xxx`，就不要去顶层找

## 列表接口

列表页主接口：

- `GET /api/v1/jobs`
- `GET /api/v1/ocr/jobs`（复用同一套逻辑，额外固定 `workflow=ocr`）

查询参数：

- `limit`：可选，默认后端内置默认值
- `offset`：可选，默认 `0`
- `status`：`queued | running | succeeded | failed | canceled`
- `workflow`：`book | ocr`
- `provider`：按 OCR provider 诊断信息过滤，例如 `mineru`

排序固定为 `updated_at DESC`（最近有变化的任务排最前，不等于最近创建）。

常用字段：

- `job_id`
- `display_name`（取值优先级：上传文件名 > 远程 URL 最后文件名 > 兜底 `job_id`）
- `workflow`
- `status`
- `trace_id`
- `stage`
- `created_at`
- `updated_at`
- `detail_url`
- `invocation`（新任务应显示 `input_protocol=stage_spec`）
- 列表响应额外返回 `data.invocation_summary`（当前分页的协议聚合统计）

推荐读取：`GET /api/v1/jobs?limit=20&offset=0`；只看失败 `?status=failed`；只看 OCR 子任务 `?limit=20&offset=0` 走 `/api/v1/ocr/jobs`。

列表接口不返回 `runtime` / `runtime.stage_history` / `failure.summary` / `artifacts`。要展示失败摘要、总耗时、下载按钮、过程时间线，点击列表项后继续请求详情接口。

推荐只把它当“最近任务入口”，不要在列表里硬塞详情页逻辑。

## Provider 校验

MinerU Token 校验：

- `POST /api/v1/providers/mineru/validate-token`

用途：

- 提交 OCR 前先校验 token 是否可用
- 提前发现过期、无效或网络问题

请求体：

```json
{
  "mineru_token": "mineru-xxxx",
  "base_url": "https://mineru.net",
  "model_version": "vlm"
}
```

`mineru_token` 必填；`base_url` 默认 `https://mineru.net`；`model_version` 默认 `vlm`。

返回 `data` 里的 `status` 固定取值：

- `valid`：Token 可用
- `unauthorized`：Token 无效
- `expired`：Token 已过期
- `network_error`：当前机器到 MinerU 连通性探测失败
- `provider_error`：MinerU 返回其他错误

前端用法：用户输入/更新 token 后调用此接口，按 `data.status` 给即时提示，只有 `valid` 才继续提交。`data.summary` 给成功提示，失败加 `operator_hint`。

实现约定：只做轻量探测校验 Authorization，不创建 OCR 任务、不上传 PDF。它是「前置校验」，与运行期失败诊断互补（运行期仍识别 `A0202` 无效 Token、`A0211` Token 过期）。

## 基础读法

- 任务状态看 `status`
- 当前阶段看 `stage`
- 是否能点按钮看 `actions`
- 是否能下载看 `artifacts` / `artifacts-manifest`
- 任务是否真完成看 `status === succeeded`
