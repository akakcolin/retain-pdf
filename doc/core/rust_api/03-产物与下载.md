# 产物与下载

这篇讲任务产物怎么发现、怎么下。

## 产物清单

主接口：

- `GET /api/v1/jobs/{job_id}/artifacts-manifest`
- `GET /api/v1/ocr/jobs/{job_id}/artifacts-manifest`

它是正式的机器发现入口。

每项常见字段：

- `artifact_key`
- `artifact_group`
- `artifact_kind`
- `ready`
- `file_name`
- `content_type`
- `size_bytes`
- `relative_path`
- `checksum`
- `source_stage`
- `updated_at`
- `resource_path`
- `resource_url`

推荐流程：

1. 先查 manifest
2. 找目标 `artifact_key`
3. 确认 `ready=true`
4. 再用 `resource_path` 或 `resource_url`

## 常见 artifact

- `source_pdf`
- `translated_pdf`
- `typst_source`
- `typst_render_pdf`
- `markdown_raw`
- `markdown_bundle_zip`
- `markdown_images_dir`
- `normalized_document_json`
- `normalization_report_json`
- `translation_manifest_json`
- `provider_result_json`
- `provider_bundle_zip`
- `pipeline_summary`
- `events_jsonl`

语义要分清四层：

- `provider_result_json` / `provider_bundle_zip`：属于 `provider raw`
- `normalized_document_json` / `normalization_report_json`：属于 `normalized`
- `markdown_raw` / `markdown_bundle_zip` / `translated_pdf`：属于 `published artifact`
- `/pdf`、`/normalized-document`、`/artifacts/{artifact_key}`：属于 `download API`

`markdown_bundle_zip` 是最适合前端直接下载的 Markdown 包：只含 `markdown/full.md` 与 `markdown/images/**`，不含原始 PDF、翻译后 PDF、provider bundle、调试 JSON。下载时加 `?include_job_dir=true`，解压根目录会从 `markdown/` 变成 `{job_id}-markdown/`。

`events_jsonl` 是任务运行期落盘的事件流导出，适合调试下载、导出、归档；但前端主界面的「事件流」tab 仍应优先读 `/events` 接口，不要把它当主展示真源。

## 下载入口

常见下载接口：

- `/pdf`
- `/markdown`
- `/normalized-document`
- `/normalization-report`
- `/download`
- `/artifacts/{artifact_key}`
- `/preview/pages/{page}?kind=source|translated&width=1200`

Markdown 相关注意：

- `/markdown` 默认返回 JSON 包装
- `/markdown?raw=true` 返回原始 Markdown
- `markdown_bundle_zip` 是最适合前端直接下载的包

页级预览图用于阅读器首屏兜底：

- 返回 `image/jpeg`
- 使用强缓存：`Cache-Control: public, max-age=31536000, immutable`
- 返回稳定 `ETag`
- 按 job 缓存在 `artifacts/` 下

对照 PDF 不要求前端本地合成：

- `GET /api/v1/jobs/{job_id}/pdf/side-by-side`，返回 `application/pdf`
- 后端读源 PDF 和最终翻译 PDF，生成并缓存 `jobs/{job_id}/artifacts/{job_id}-side-by-side.pdf`
- 每页左侧原文、右侧译文；页数不一致时输出页数取最大值，缺失一侧留空
- 源 PDF 或译文 PDF 未 ready 时返回 `404`

旧接口与发现入口的关系：

- `/pdf`、`/markdown`、`/normalized-document` 是稳定下载入口
- `artifacts-manifest` 是稳定发现入口
- 详情里的 `artifacts.pdf` / `artifacts.markdown` / `artifacts.bundle` 是推荐的页面状态字段
- 同级的 `pdf_url` / `markdown_url` / `bundle_url` 是兼容别名，不建议新代码依赖
- 注意：这里的「旧接口」指当前 API 里的稳定资源入口，不是旧任务目录布局。任务若仍来自 `originPDF/jsonPDF/transPDF/typstPDF` 旧布局或绝对路径 artifact，下载入口会直接拒绝，必须重跑

## 四层边界

后端对外看四层：

- `provider raw`
- `normalized`
- `published artifact`
- `download API`

不要把目录结构当公开契约。

## 排错入口

如果按钮不可点，先看：

- `actions.*.enabled`
- `artifacts.*.ready`
- `artifacts-manifest.items[].ready`

如果下载失败，优先看：

- `failure`
- `runtime`
- `log_tail`
- `/events`
